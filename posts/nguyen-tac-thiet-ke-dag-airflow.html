Nguyên tắc thiết kế DAG Airflow

2026-11-23 | Tag: Airflow, data-engineering, dag, orchestration

1. Lịch chạy

Chọn lịch theo nhịp cập nhật của nguồn data, không theo thói quen. Đặt catchup có chủ đích và đặt start_date cố định, tránh dùng thời gian động.

2. Phụ thuộc task

Mỗi task chỉ làm một việc rõ ràng, ví dụ extract, load hoặc transform. Khai báo phụ thuộc tường minh để dễ đọc và dễ chạy lại từng bước. Tránh DAG quá lớn, hãy tách theo nguồn hoặc theo domain.

3. Retry

Đặt retries và retry_delay cho lỗi tạm thời như mạng hay API quá tải. Có thể dùng exponential backoff. Lỗi logic thì retry không giúp được gì, cần có cảnh báo để xử lý.

4. Idempotent

Chạy lại cùng một kỳ phải cho cùng kết quả, không nhân đôi data. Hãy ghi theo phân vùng ngày hoặc dùng MERGE thay vì INSERT thuần, và lấy dữ liệu theo khoảng thời gian của kỳ chạy.

Code minh họa

Đây là đoạn code minh họa, không phải DAG chạy thật.

from datetime import datetime, timedelta
from airflow import DAG
from airflow.operators.python import PythonOperator

def extract(ds, **_): ...   # lấy data theo ngày ds
def load(ds, **_): ...      # ghi đè phân vùng ds

with DAG(
    dag_id="demo_daily",
    start_date=datetime(2024, 1, 1),
    schedule="@daily",
    catchup=False,
    default_args={"retries": 3, "retry_delay": timedelta(minutes=5)},
) as dag:
    t1 = PythonOperator(task_id="extract", python_callable=extract)
    t2 = PythonOperator(task_id="load", python_callable=load)
    t1 >> t2

Lưu ý: tham số schedule dùng cho Airflow 2.4 trở lên. Bản cũ hơn dùng schedule_interval.
